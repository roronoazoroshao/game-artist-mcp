# Linh Hỏa — Thanh Liên U Hỏa (Godot 4)

**Status:** V2 shader-based, editable *art prototype*. **Not** independently approved artwork or production-ready VFX.

## Visual brief
- Xianxia 2.5D isometric spell/fire; pale gold spirit core wrapped by jade-cyan flame and two lotus petals.
- Silhouette should read at 64px; finer rune-ring geometry appears at 128px.
- Animation is procedural and deterministic from time: three time-offset flame plumes with 4-octave advection-noise shader, nineteen drifting embers and a pulsing Godot PointLight2D.
- The base is an isometric ellipse; the game sandbox includes a hexagonal basalt altar, diamond courtyard and two monoliths.
- No external image-generation models, stock art or downloaded textures were used. Moving shader noise is fully procedural. The native Godot light texture is generated pixel-by-pixel in code.

## Editability
The flame is the reusable **linh_hoa.tscn** scene. Native parameters and time phases live in **linh_hoa.gd**, noise/flow/color in **flame_field.gdshader**, layer settings in **flame_field.gd**, the native PointLight2D in **spirit_light.gd** and foreground jade petals in **lotus_front.gd**. No flattened painting/texture dependency. **showcase.tscn** and **showcase.gd** are only the demo world. Thumbnails are actual Godot SubViewport outputs; they are not PNGs scaled in an external editor.

## Run
```bash
godot --path examples/linh-hoa
```
Headless is insufficient to prove real OpenGL rendering. On Linux with Xvfb and software OpenGL:
```bash
xvfb-run -a godot --path examples/linh-hoa -- --capture-native
```
The capture command creates `captures/game-00.png`…`game-03.png` (960×540) at 0, 0.34, 0.78 and 1.21s, plus actual **64×64** and **128×128** Godot SubViewport framebuffer captures. Node-based evidence checks:
```bash
npm ci --ignore-scripts
node --test test/linh-hoa-framebuffer.test.mjs
```
For a 24-sample in-engine motion sequence and on/off lighting ablation run:
```bash
xvfb-run -a godot --path examples/linh-hoa -- --capture-motion
xvfb-run -a godot --path examples/linh-hoa -- --capture-light-ab
```
The animated GIF is generated by assembling **24 real Godot framebuffers** (18 Hz sampling at pinned animation times), downscaled to 480×270 purely for preview. The original 24 PNGs live in ignored `captures/motion-temp/`; the GIF is checked into Git. This is not an AI-generated animation.

## Verification boundary
- Source scene and runtime screenshots proven on Godot **4.4.1**, Linux/Xvfb/OpenGL Mesa llvmpipe.
- Demo scene ≠ integration into the user's actual external game. Tested only inside this repo's sandbox.
- Four discrete scene PNGs and an additional 24-frame preview prove non-constant, temporally changing rendered output; they do **not** certify real-time smoothness at 60fps, mobile GPU behavior, or artistic quality.
- Real lighting verified with equal-phase on/off ablation and a genuine frame difference on surrounding courtyard pixels.
- 64px readability is manually observed; technical color-count and frame-diff tests do not judge aesthetic merit.

## Outstanding visual defects
1. Flowing shader flame now changes contour and interior over time, but still appears overly blurred/cloudlike, especially at scene scale. Needs painterly stroke detail and sharper lobe segmentation.
2. The spell circle and jade lotus still risk reading as decorative VFX UI rather than grounded physical ritual geometry at 64/128px.
3. Engine-native local lighting exists, with observed in-scene on/off ablation, but nuanced contact bounce, bloom control, volumetric occlusion and physical material response still need art direction.
4. 24 Godot samples do not prove stable frame pacing, 60fps performance, or production-ready fluid-motion perception.
